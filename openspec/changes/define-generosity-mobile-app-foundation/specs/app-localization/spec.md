## ADDED Requirements

### Requirement: Initial Supported Languages
The mobile app SHALL support Spanish and English as the initial user-facing languages.

#### Scenario: User opens app in Spanish
- **WHEN** the user's selected or device language is Spanish
- **THEN** the app displays supported user-facing app text in Spanish

#### Scenario: User opens app in English
- **WHEN** the user's selected or device language is English
- **THEN** the app displays supported user-facing app text in English

### Requirement: App-Controlled Text Localization
All app-controlled user-facing text SHALL be externalized for localization and SHALL have Spanish and English values before release.

#### Scenario: Screen uses app-controlled text
- **WHEN** a screen displays labels, actions, empty states, errors, permissions rationale, onboarding text, or settings text
- **THEN** those strings are provided through localization resources in both Spanish and English

### Requirement: Shared Domain Label Codes
The shared module SHALL expose stable codes instead of hard-coded display text for localized domain labels.

#### Scenario: UI displays a center category
- **WHEN** the app displays a Kindness Center category
- **THEN** the platform UI resolves the shared category code to the active locale's label

### Requirement: Localized Imported Content
Imported Kindness Center content SHALL support localized text fields when translations are available and SHALL fall back deterministically when the selected locale is missing.

#### Scenario: Imported content has selected locale
- **WHEN** center content includes text for the active locale
- **THEN** the app displays the active-locale text

#### Scenario: Imported content is missing selected locale
- **WHEN** center content does not include text for the active locale
- **THEN** the app displays fallback content without crashing or showing an internal localization key

### Requirement: Notification Localization
Notification titles and bodies generated by the mobile app SHALL use the user's active supported locale.

#### Scenario: User receives reminder notification
- **WHEN** a reminder notification is generated for a user whose active locale is Spanish
- **THEN** the notification title and body use Spanish localization resources

### Requirement: No Automatic Machine Translation
The mobile app SHALL NOT automatically machine-translate Kindness Center names, descriptions, needs, or user-entered contribution notes as part of this foundation change.

#### Scenario: Content lacks translation
- **WHEN** a Kindness Center description is only available in one language
- **THEN** the app displays the available source content according to fallback rules rather than generating an automatic translation

### Requirement: Language Setting
User settings SHALL offer Use device language, Spanish and English, with the saved choice visibly selected. Settings SHALL be reachable for guests and registered users. Language preference SHALL be installation-specific, persist across restarts and account entry/exit, and SHALL NOT require network access.

#### Scenario: Change language in settings
- **WHEN** a user chooses Spanish from user settings while the device uses English
- **THEN** the app immediately switches to Spanish and the setting still reads Spanish after restart

#### Scenario: Return to automatic language
- **WHEN** the user chooses Use device language after a manual override
- **THEN** the override is cleared and the app immediately resolves the current device language preferences

#### Scenario: Same account on different devices
- **WHEN** an account signs in on two installations with different device-language settings
- **THEN** one installation does not silently overwrite the other's language mode

### Requirement: Live Locale Propagation
A language change SHALL update visible app copy, domain labels, validation errors, dates, localized catalog text, search/sort results and notification language without restarting or losing entered form data. Pending local notifications SHALL use the new language, and the backend SHALL receive the installation locale for later remote alerts when connected.

#### Scenario: Switch language while searching
- **WHEN** a user changes language with a search or category filter active
- **THEN** both map and list recompute against the active localized content while preserving the user's query and selected categories

#### Scenario: Device language changes in automatic mode
- **WHEN** the user changes device language and resumes the app in Use device language mode
- **THEN** the app resolves the new preferences without changing stored dates, quantities or the content of user-entered notes

### Requirement: Natural Unicode Copy
Mobile UI resources and sample catalog content SHALL use correct Spanish accents,
ñ, punctuation and natural Spanish/English wording. App copy SHALL use native
resource catalogs rather than duplicate per-language branches in screen code.
User-entered text and real center names SHALL retain their source spelling.

#### Scenario: Spanish content is displayed
- **WHEN** a user opens Spanish settings or a sample center detail
- **THEN** text such as Español, Años Dorados, México and Útiles escolares retains its Unicode characters

### Requirement: Extensible Language Registry
Both native language selectors SHALL use the shared enabled-language registry,
display each language by its native name and retain the installation-specific
system/manual mode. Adding a reviewed language SHALL require catalog/registry
configuration rather than binary Spanish-versus-English screen logic. Missing
UI translations SHALL fall back to English and SHALL fail catalog validation
before release. Layout direction SHALL follow the active language.

#### Scenario: Another language is prepared
- **WHEN** a developer adds a language to the registry
- **THEN** both settings selectors include it and validation requires its native UI, plural and permission resources before release

### Requirement: Native Whole-Message Formatting
Quantity messages SHALL use complete translated plural resources with typed
placeholders. Displayed numeric metrics SHALL use native locale formatting.

#### Scenario: A remaining quantity changes
- **WHEN** the remaining count changes from one to fifteen in Spanish
- **THEN** the app displays Falta 1 unidad and Faltan 15 unidades using native plural selection

### Requirement: Unicode Search Matching
Discovery SHALL compare case- and diacritic-folded search keys without changing
stored or displayed content, including canonically decomposed Spanish characters.

#### Scenario: A user omits a diacritic while searching
- **WHEN** the Spanish sample catalog is searched for ninos or niños
- **THEN** the same matching center is returned and displayed text retains niños

## MODIFIED Requirements

### Requirement: Locale Selection
The app SHALL default to Use device language. Without a manual override it SHALL choose the first Spanish or English language in the device's ordered preferences, normalizing regional variants, or English if none match. A persisted explicit Spanish/English choice SHALL take precedence until the user returns to device mode. Resolution SHALL precede the first visible welcome screen.

#### Scenario: User selects in-app language
- **WHEN** the user selects Spanish or English inside the app
- **THEN** the app uses that selected language for supported user-facing text

#### Scenario: Device locale is unsupported
- **WHEN** no explicit choice exists and none of the device's preferred languages is Spanish or English
- **THEN** the app uses the configured English fallback

#### Scenario: Regional Spanish on a fresh installation
- **WHEN** a fresh installation reads es-MX as the first supported device preference
- **THEN** its welcome and subsequent screens use Spanish without user intervention

#### Scenario: A supported secondary device language exists
- **WHEN** device preferences are French followed by Spanish and the app is in device mode
- **THEN** the app selects Spanish rather than falling directly back to English

#### Scenario: Manual choice survives a device-language change
- **WHEN** Spanish was explicitly saved and the device changes to English
- **THEN** the app remains in Spanish until its setting is changed
