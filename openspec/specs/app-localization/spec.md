# app-localization Specification

## Purpose
Define the multilingual behavior for the Generosity mobile app, including Spanish and English support, locale selection, localized app-controlled text, localized imported content fallback, and notification localization.

## Requirements
### Requirement: Initial Supported Languages
The mobile app SHALL support Spanish and English as the initial user-facing languages.

#### Scenario: User opens app in Spanish
- **WHEN** the user's selected or device language is Spanish
- **THEN** the app displays supported user-facing app text in Spanish

#### Scenario: User opens app in English
- **WHEN** the user's selected or device language is English
- **THEN** the app displays supported user-facing app text in English

### Requirement: Locale Selection
The mobile app SHALL select a supported locale from the user's in-app language choice when available, otherwise from the device locale when supported, otherwise from the configured fallback locale.

#### Scenario: User selects in-app language
- **WHEN** the user selects Spanish or English inside the app
- **THEN** the app uses that selected language for supported user-facing text

#### Scenario: Device locale is unsupported
- **WHEN** the user has not selected an in-app language and the device locale is not Spanish or English
- **THEN** the app uses the configured fallback locale

### Requirement: App-Controlled Text Localization
All app-controlled user-facing text SHALL be externalized for localization and SHALL have Spanish and English values before release.

#### Scenario: Screen uses app-controlled text
- **WHEN** a screen displays labels, actions, empty states, errors, permissions rationale, onboarding text, or settings text
- **THEN** those strings are provided through localization resources in both Spanish and English

### Requirement: Shared Domain Label Codes
The shared module SHALL expose stable codes instead of hard-coded display text for localized domain labels.

#### Scenario: UI displays a center category
- **WHEN** the app displays a Kindness Center category
- **THEN** the platform UI resolves the shared category code to the active locale's label

### Requirement: Localized Imported Content
Imported Kindness Center content SHALL support localized text fields when translations are available and SHALL fall back deterministically when the selected locale is missing.

#### Scenario: Imported content has selected locale
- **WHEN** center content includes text for the active locale
- **THEN** the app displays the active-locale text

#### Scenario: Imported content is missing selected locale
- **WHEN** center content does not include text for the active locale
- **THEN** the app displays fallback content without crashing or showing an internal localization key

### Requirement: Notification Localization
Notification titles and bodies generated by the mobile app SHALL use the user's active supported locale.

#### Scenario: User receives reminder notification
- **WHEN** a reminder notification is generated for a user whose active locale is Spanish
- **THEN** the notification title and body use Spanish localization resources

### Requirement: No Automatic Machine Translation
The mobile app SHALL NOT automatically machine-translate Kindness Center names, descriptions, needs, or user-entered contribution notes as part of this foundation change.

#### Scenario: Content lacks translation
- **WHEN** a Kindness Center description is only available in one language
- **THEN** the app displays the available source content according to fallback rules rather than generating an automatic translation
